# Генерация телефонных номеров

Согласовано 23.09.2026: выдавать номера из регионов, где местное время **09:00 включительно — 21:00 исключительно**. Если подходящих диапазонов нет, выбирать случайный номер из всех известных региональных диапазонов. Карточку не скрывать.

## Источник и точность

- Первоисточник диапазонов: [реестр Минцифры](https://opendata.digital.gov.ru/registry/numeric/downloads), выгрузка `DEF-9xx.csv`.
- Использована производная копия [DimmKG/ru-phone-base](https://github.com/DimmKG/ru-phone-base/tree/40d0bb24311f294073ee6715227a496647fafcd6), commit `40d0bb24311f294073ee6715227a496647fafcd6`.
- Дата сборки снимка: **2026-09-04T03:18:16.748Z**. Загружен 23.09.2026. Свежая официальная выгрузка была недоступна из среды разработки; это копия реестра, не проверка его текущего состояния онлайн.
- В `source/` сохранены неизменённые `mobile.json`, `regions.json`, `timezones.json`, `meta.json`, лицензия и ревизия. Контрольные суммы файлов проверяются при каждой генерации. В исходном DEF-снимке 17 060 строк; после объединения смежных интервалов приложение использует 13 882 диапазона в 91 группе регионов. 33 блока без региональной привязки исключены.
- Часовые пояса взяты из той же копии (OSM и таблица соответствий её автора); местное время рассчитывает браузер через IANA-идентификаторы и `Intl.DateTimeFormat`. [IANA tzdb](https://www.iana.org/time-zones).
- Это привязка выделенного диапазона, а не определение текущего местонахождения человека. Поездки, переносы номера, изменения реестра, ошибочное время устройства и устаревшая база часовых поясов могут дать неточный результат. Наличие диапазона в реестре не подтверждает, что конкретный номер подключён или что человек бодрствует.

## Алгоритм

1. Получить текущий момент с часов устройства (`new Date()`), без геолокации или сетевого запроса. Часовой пояс самого пользователя не требуется: один и тот же момент переводится в каждый предполагаемый пояс получателя.
2. Отобрать группы, где во **всех** возможных поясах сейчас 09:00–20:59. Для Якутии учитываются все указанные в источнике пояса, а не только время Якутска. Общероссийские диапазоны без географической привязки не используются.
3. Если таких групп нет, использовать все региональные группы без ограничения времени. Это также резервный вариант для недостоверной даты или отсутствующих в браузере часовых поясов.
4. Выбрать случайный номер равновероятно по ёмкости допустимых диапазонов. Не генерировать произвольные цифры вне выделенных интервалов.
5. Форматировать как `+7 (9ХХ) ХХХ-ХХ-ХХ`. Повторные `*PHONE_NUM*` в одной карточке используют один номер. Уже выданный номер сохраняется в текущем ходе и не меняется при восстановлении игры, даже если время изменилось.

## Сборка и обновление

`npm run import:data` подготавливает и карточки из XLSX, и телефонную базу. Эту команду автоматически вызывают dev, тесты, проверка типов и production build. Сборка и игра не обращаются в сеть за номерами. База входит в JS приложения и его офлайн-кэш.

Для обновления выбрать новую зафиксированную ревизию источника и скачать **вместе** четыре JSON-файла из `src/data/` и `LICENSE`, сохраняя исходные байты. Обновить `source/revision.txt`, дату и ссылку в этом документе и `public/phone-numbering-notice.txt`. Затем выполнить `npm run import:data`, `npm run typecheck`, `npm test -- --maxWorkers=1`, `npm run build`. При неизвестных регионах, пересечениях диапазонов или несовпадении контрольных сумм импорт завершится ошибкой. Исправлять нужно источник/преобразователь, не `src/generated/phone-data.ts`.

Это отдельный справочник телефонных диапазонов. Единственным источником карточек и паков остаётся `docs/Паки и вопросы.xlsx`.
